# H3 WebUI 更新包 v2（2026-11-22）

> 只更新 WebUI 两个文件，**不动工作流模板、不动模型、不动 ComfyUI**。

## 修了什么

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 1 | **视频列表重复** | 每条视频出现两次（`X.mp4` 和 `X-audio.mp4`） | 按「目录+基础名」去重，保留**带音轨**那份 |
| 2 | **混入非视频** | 列表里有解不出画面的条目 | 加校验：必须有视频流、时长>0、体积>20KB，否则跳过 |
| 3 | **重启后任务丢失** | 进度秒不走了、结果不出来（我改代码重启过 WebUI） | 任务记录落盘到 `jobs.json`，启动自动续跟；前端 404 时自动接上正在跑的任务 |
| 4 | **没有历史浏览** | 只能看"本次生成记录" | 新增 **作品库**：缩略图网格，可点播/下载/一键续接 |
| 5 | **没法按编号找** | 只能翻文件名 | 每条视频分配**稳定编号** `#N`（`library.json` 持久化），支持输入编号跳转和 `/api/video?no=N` |

## 新增的接口

| 接口 | 说明 |
|---|---|
| `GET /api/thumb?rel=...` 或 `?no=N` | 视频缩略图（取 1/3 处那一帧，320px JPEG，按文件名+mtime 缓存到 `thumbs/`） |
| `GET /api/video?no=N` | 按编号取视频（支持 Range，播放器可拖进度） |
| `GET /api/outputs` | 现在返回去重后的列表，每条含 `no`（编号）和 `mtime` |

## 怎么更新（对面电脑）

### 方式 A：跑脚本（推荐）

```powershell
# 解压后进入本目录，把 <项目目录> 换成对方实际的部署目录
powershell -ExecutionPolicy Bypass -File .\apply-update.ps1 -Target "<项目目录>"
```

脚本会：备份旧文件 → 覆盖 `app.py` 和 `static\index.html` → 停掉 8190 上的旧进程 → 用原 Python 重启 → 轮询 `/api/health` 确认起来。

### 方式 B：手动

1. 停掉 WebUI（关掉 `启动.bat` 的窗口，或 `Stop-Process` 掉占 8190 的进程）
2. 把 `webui\app.py` 覆盖到 `<部署目录>\app.py`
3. 把 `webui\static\index.html` 覆盖到 `<部署目录>\static\index.html`
4. 重新双击 `启动.bat`
5. 浏览器 **Ctrl+F5** 强制刷新（前端是静态文件，可能有缓存）

## 更新后应该看到

1. 作品库里去掉了重复项（数量约为原来的一半）
2. 每格左上角有金色 `#编号`
3. 右上角「编号」框输入数字 → 播放
4. `curl http://127.0.0.1:8190/api/outputs` → `items` 里每项有 `no` 字段，`next` 是下一个可用编号

自检命令：

```powershell
curl.exe -s http://127.0.0.1:8190/api/health
curl.exe -s http://127.0.0.1:8190/api/outputs
curl.exe -s -o NUL -w "%{http_code}`n" "http://127.0.0.1:8190/api/thumb?no=1"
```

期望：`{"comfy":true,...}` / items 非空且无重复 / `200`

## 兼容性

- **不需要迁移数据**：`library.json`、`jobs.json`、`thumbs/` 都会在首次访问时自动创建
- 首次打开会按生成时间给已有视频分配 `#1…#N`（最早的 = #1），之后**编号固定不重排**
- 旧的 `jobs.json` 不存在也没关系，只是历史任务列表从空开始
- 依赖没变：还是 `aiohttp` / `av` / `Pillow`（ComfyUI 的 venv 都有）
- 如果对面改过 `app.py`（比如自定义了路径），别直接覆盖——只看 `api_outputs`、`api_thumb`、`api_video`、`job_worker`、`on_startup` 这几处改动手工合并
