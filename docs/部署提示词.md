你要在一台**已装好 ComfyUI Desktop** 的笔记本上，复刻一套已经在另一台机器上跑通的方案：DSH 装一个 ComfyUI 联动插件、下 MiniMax-H3 模型、建两套工作流模板、最后能通过对话直接出片并支持"接着上一段继续"。

## 铁律（先读，能省你几小时）

1. **不要照抄路径**。下面的路径是参考机上的，你的机器可能完全不同。每一步先用命令探测，再决定放哪。

## 第 1 步：装 DSH 的 ComfyUI 联动插件

用 `plugin_manager` 的 `install_bundle`，target 传：

```
github:YuChenLiao/dsh-comfyui-workbench
```

安装成功的判据（不要只看日志，看返回值）：

- 返回里 `"application": "applied"`，`warnings` 为空
- 本会话工具列表里出现 `comfyui_run` / `comfyui_workflow` / `comfyui_runs` 等
- 出现一个 `comfyui-workbench` 技能

装完立刻验证：调 `comfyui_workflow`（不带参数），应能列出模板清单（此时是空的，正常）。

### ⚠️ 这个插件的已知坑（必读）

**它把 ComfyUI 的 `/object_info` 缓存在自己的进程里，永不刷新。** 所以只要你后来新装了自定义节点或新模型，`comfyui_run` 的预检就会误报"缺节点"。

**解法**（每次装完新东西都要做一次）：

```
plugin_manager set_bundle  target=dsh-comfyui-workbench  enabled=false
plugin_manager set_bundle  target=dsh-comfyui-workbench  enabled=true
```

另外：**工具等待上限是 30 分钟**。超时后那次运行会被标记成 `unknown`，而且**产物不会自动归档**——这时用 `comfyui_run { promptId: "..." }` 续查一次，它会把产物补收进 `outputDir` 并写 sidecar。

- **下载到同名临时文件（`.part`），校验长度 + SHA256 通过后再改名**——不要边下边改目标名

## 第 3 步：装自定义节点（只装必要的）

### 必装：VideoHelperSuite（输出节点）

```powershell
cd <ComfyUI>/custom_nodes
git clone --depth 1 https://github.com/Kosinkadink/ComfyUI-VideoHelperSuite
<venv python> -m pip install --no-deps imageio-ffmpeg
```

> 为什么不用内置的 `SaveVideo`：它的 `format=auto` 会把码率压到 ~2000 kbps；而且**宽高是奇数时它的 h264 重编码会直接失败**（`avcodec_open2 ... EINVAL`）。VHS 走外部 ffmpeg，码率可控。

### 按需：ComfyUI-Easy-Use（只有要跑"用户原始工作流"才需要）

原始工作流里有 3 个 `easy cleanGpuUsed`（纯清显存）。如果你用第 4 步的社区模板，**完全不需要这个包**。要用就：

```powershell
git clone --depth 1 https://github.com/yolain/ComfyUI-Easy-Use
<venv python> -m pip install -r ComfyUI-Easy-Use/requirements.txt
```

⚠️ 装它时如果 ComfyUI 正在运行，`cv2.pyd` 被占用会报 `WinError 5 拒绝访问`。解法：`--no-deps` 分批装，或先停 ComfyUI。

### 按需：SageAttention（只有要跑原始工作流的 Sage 节点才需要）

**社区 8 GB 实测结论：sm_120 上 Sage 是负优化**（比 comfy-kitchen 慢 1.27×、误差 2.4×，而且会屏蔽 `ModelAttentionBackend`）。**推荐的做法是不装，用 kitchen 后端**。

## 第 4 步：建两套工作流模板

DSH 插件的模板存在 `<profile 数据目录>/workflows/`，每个模板 3 个文件：`<id>.json`（API 格式图）、`<id>.schema.json`（变量声明）、`<id>.meta.json`（标题备注）。

模板 id 用：`minimax-h3-ref2v-community-multi`（单段/多图）和 `minimax-h3-ref2v-continue`（续接）。

### 4.1 拿一张公开的 API 格式基准图

```
https://raw.githubusercontent.com/FlowForgeLabAi/MiniMax-H3-8GB-Workflows/main/api/H3_Balanced.api.json
```

这是社区 8 GB 实测的 API 格式工作流（23 个节点），已经用 `comfy-kitchen` 注意力后端、包含 `MiniMaxH3SigmaShift`。**它是 fl2va 版**，你要改成 ref2va 版：

### 4.2 改动清单（对照节点 id）

| 节点 | 改什么 |
|---|---|
| `1` UNETLoader | `unet_name` → `minimax_h3_ref2va_pruned_int8_convrot.safetensors` |
| `7` LoraLoaderModelOnly | `lora_name` → `minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors`，`strength_model` 1.0 |
| `10` CLIPLoader | `clip_name` → `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`（`type` 保持 `minimax`） |
| `17` / `18` VAELoader | `minimax_h3_video_vae_int8_convrot.safetensors` / `minimax_h3_audio_vae_fp32.safetensors` |
| `12` LoadImage | 换成你自己的参考图文件名（放进 ComfyUI 的 input 目录） |
| `13` ResolutionSelector | `aspect_ratio` `"3:4 (Portrait Standard)"`、`megapixels` **0.75**、`multiple` 32 → 得到 768×1024 |
| `14` PrimitiveFloat | 时长（秒）。工作流用它算帧数，公式见下 |
| `11` PrimitiveStringMultiline | 你的提示词 |
| `33` VHS_VideoCombine | 加 4 个字段：`"crf": 12, "pix_fmt": "yuv420p", "save_metadata": true, "trim_to_audio": false` |

**时长 → 帧数**：`f = max(5, round(秒*24))`，再吸附到网格：`f = f + (5 - f % 17) % 17`。例：3 秒→73 帧、5 秒→124 帧、15 秒→362 帧。**模型训练区间是 124–362 帧（5–15 秒），低于 5 秒质量明显下降。**

> `crf` / `pix_fmt` 这些**不在 `/object_info` 里**（是 VHS 的动态子控件），但作为扁平字段写进节点 inputs 是**有效的**，实测码率从 2559 → 7259 kbps。

改完存成 `minimax-h3-ref2v-community-multi.json`。

### 4.3 续接模板

复制上面那份，加 2 个节点：

```json
"47": {"class_type": "LoadImage", "inputs": {"image": "last_frame.png"}},
"48": {"class_type": "MiniMaxH3AddGuide",
       "inputs": {"positive": ["16", 0], "latent": ["16", 1], "vae": ["17", 0],
                  "image": ["47", 0], "frame_idx": 0}}
```

把 `8` BasicGuider 的 `conditioning` 从 `["16", 0]` 改成 `["48", 0]`。
存成 `minimax-h3-ref2v-continue.json`。

> 原理：`AddGuide` 把"上一段末帧"钉在新片段的第 0 帧，接缝在生成内部解决。实测首帧与锚点几乎完全一致。

### 4.4 schema（变量声明）

`.schema.json` 里 `vars` 每项形如：

```json
{"name": "image1", "label": "参考图 1", "type": "image", "group": "basic",
 "bind": "12.inputs.image", "default": "hero_ref_1.png"}
```

`bind` 格式是 `<节点id>.inputs.<输入名>`。建议声明这些变量：

- `image1`…`image7`（多图模板 7 个槽；参考图节点 12、40–45；对应 `16.inputs["ref_images.ref_image_N"]`）
- `prompt` → `11.inputs.value`
- `duration` → `14.inputs.value`
- `megapixels` → `13.inputs.megapixels`
- `steps` → `22.inputs.steps`
- `sampler_name` → `21.inputs.sampler_name`
- `scheduler` → `22.inputs.scheduler`
- `lora` / `lora_strength` → `7.inputs.lora_name` / `7.inputs.strength_model`
- `seed` → `20.inputs.noise_seed`
- `crf` → `33.inputs.crf`
- 续接模板再加 `last_frame` → `47.inputs.image`、`frame_idx` → `48.inputs.frame_idx`

`.meta.json` 至少写：`{"title": "...", "description": "...", "enabled": true}`。

建完后用 `comfyui_workflow { workflowId }` 验证：`missingNodes` 必须为空、`models` 必须都对得上、`inputs` 里能看到你声明的变量。

## 第 5 步：验收（必须逐条实测，别跳）

1. **单段 3 秒 / 1 张参考图**：约 3 分钟，应出 73 帧、768×1024、带音轨的 mp4
2. **单段 5 秒 / 7 张参考图**：约 8–10 分钟，应出 124 帧
3. **衔接**：拿第 1 条视频的末帧当 `last_frame`、`frame_idx=0`，再跑 3 秒；**新片首帧应与上段末帧几乎一致**
4. **码率**：`crf 12` 时 5 秒片应在 4 MB 以上（≈7000 kbps）；如果只有 1.5 MB，说明 crf 没生效
5. **拼接**（可选）：两段参数一致时可直接 `ffmpeg -f concat -c copy` 无损拼接

汇报时给：每条的视频路径、帧数、时长、真实耗时（用 ComfyUI `/history` 的 `execution_start → execution_success`，**不要用插件返回的 `elapsedMs`——那是从提交时刻算的含排队时间**）。

## 第 6 步：提示词写法（决定成片质量的一半）

模型对"短的自然语言"跟随很差，必须给结构化提示词：

```
参考 <Picture 1>–<Picture 7> 中的同一角色：外貌、服装、发型与画风以参考图为准，不要改变。

[Shot 1] 固定镜头，close-up portrait，head and shoulders。
0.0–1.5 秒：双手举到脸旁做猫爪，歪头眨眼。
1.5–3.0 秒：双手在胸前比出爱心，轻轻晃动。

镜头固定，面部清晰，细节丰富。
```

三条硬规则：

1. **必须写镜头语言**：`full body shot, head to toe`（全身）或 `close-up portrait, head and shoulders`（近景）。实测前者脸只有 ~100 px、后者 ~350 px——**构图决定脸有没有细节**
2. **时间轴要铺满**：有几个镜头写几个 `[Shot N]`，并给秒级切点。只写 `[Shot 1]` 但时长 10 秒，后段模型会自己填空景、主体消失
3. **运镜要有落点**：写 `toward X, and comes to rest at a medium shot`；只写"小幅度慢速推进"会一路推过头。同时写"保持构图不变"和"推镜"是自相矛盾
